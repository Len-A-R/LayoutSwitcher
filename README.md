# LayoutSwitcher

Минималистичная утилита для Windows, которая исправляет текст, набранный в неправильной раскладке, и меняет регистр без повторного ввода.

## Возможности

* Конвертация раскладки, например `ghbdtn` → `привет`
* Верхний, нижний и инвертированный регистр
* Обработка выделенного текста
* Обработка последнего набранного слова без использования clipboard
* Автозагрузка и трей-иконка текущей раскладки
* Защита от запуска нескольких экземпляров

## Горячие клавиши

| Комбинация | Действие |
| --- | --- |
| `Shift` + `Shift` | Конвертировать раскладку |
| `LCtrl` + `LCtrl` | ПРЕОБРАЗОВАТЬ В ВЕРХНИЙ РЕГИСТР |
| `RCtrl` + `RCtrl` | преобразовать в нижний регистр |
| `LCtrl` + `RCtrl` | ИнвЕрТиРоВаТь РеГиСтР |

Интервал между завершёнными нажатиями — 500 мс. Длительное удержание клавиши и autorepeat не считаются двойным нажатием.

## Системные требования

* Windows 10 / Windows 11
* Английская US (`0x0409`) и русская (`0x0419`) раскладки

## Установка

1. Соберите проект в Delphi/RAD Studio для Win32 или Win64.
2. Запустите `LS.exe`.
3. Приложение свернётся в системный трей.
4. Через меню трей-иконки можно включить автозагрузку или завершить приложение.

## Диагностика

По умолчанию для каждого запуска создаётся журнал в `%LOCALAPPDATA%\LayoutSwitcher\Diagnostics`. Пользователь может сразу включить или отключить эту функцию флажком **«Вести диагностический журнал»** в окне настроек; выбор сохраняется в профиле пользователя. При отключённой диагностике приложение не создаёт журналы, MiniDump и маркер незавершённого сеанса. Открыть уже существующую папку можно командой **«Открыть папку диагностики»** в меню трей-иконки.

Журнал содержит версию и разрядность сборки, ОС, этапы и результат преобразования, класс целевого окна, ошибки Raw Input, `SendInput` и clipboard. Сам набранный или выделенный текст в журнал не записывается.

При исключении дополнительно создаётся MiniDump (`.dmp`). Если программа неожиданно завершилась, для анализа нужны последние файлы `.log` и `.dmp` из этой папки. Файл `last-session.running`, оставшийся после завершения процесса, помечает незавершённый сеанс.

## Как устроена обработка ввода

Клавиатура и мышь отслеживаются через Raw Input (`RIDEV_INPUTSINK` / `WM_INPUT`). Это обычные асинхронные сообщения окна: LayoutSwitcher не встраивается в глобальную цепочку `WH_KEYBOARD_LL` и не может задержать keyboard hook ShareX. Остановка процесса на breakpoint или исключении также не блокирует системную клавиатуру и мышь.

Собственный ввод выполняется пакетами через `SendInput` и помечается уникальным `dwExtraInfo`, чтобы синтетические события самой утилиты не попадали обратно в отслеживаемое слово.

Целевой текст определяется в следующем порядке:

1. Выделение или слово перед кареткой в стандартном Edit/RichEdit (включая Блокнот) — читается и заменяется напрямую.
2. Последнее слово из локального буфера ввода для остальных редакторов — clipboard не используется.
3. Для VS Code, браузеров и других современных редакторов выделение сначала читается через Windows UI Automation `TextPattern` — без изменения clipboard.
4. Только если редактор не предоставляет `TextPattern`, выполняется контролируемый `Ctrl+C` fallback.

Перед отправкой `Ctrl+C` утилита дожидается физического отпускания `Shift`/`Ctrl`/`Alt`/`Win` и даёт целевому окну короткое время на обработку `KeyUp`. Это важно для Electron-редакторов: иначе VS Code иногда воспринимает копирование после двойного `Shift` как `Ctrl+Shift+C`.

Clipboard fallback считается успешным только после изменения `GetClipboardSequenceNumber`. Доступ к clipboard повторяется при кратковременной блокировке другим процессом. Перед копированием программа создаёт независимые копии доступных форматов: текста, HTML/RTF, PNG/DIB, bitmap, metafile и других блоков глобальной памяти. Восстановление выполняется через `SetClipboardData`, без повторного использования чужого `IDataObject`, `OleSetClipboard` и `OleFlushClipboard`. В восстановленный объект добавляется системный формат `ExcludeClipboardContentFromMonitorProcessing`, поэтому Windows не создаёт его повторную запись в истории и не отправляет во включённую облачную синхронизацию. Неподдерживаемый формат пропускается с записью его идентификатора в журнал. Если `Ctrl+C` был проигнорирован и clipboard не изменился, снимок освобождается без лишней перезаписи буфера.

После преобразования одного слова локальный буфер запоминает уже преобразованный вариант. Поэтому повторное нажатие преобразует его обратно без `Ctrl+C` и без обращения к clipboard.

Раскладка переключается только у контрола с фокусом. `HWND_BROADCAST` и `AttachThreadInput` не используются.

## Ограничения

* Windows запрещает `SendInput` в приложение с более высоким уровнем прав. Для редактора, запущенного от администратора, LayoutSwitcher также нужно запускать от администратора.
* Игры, защищённые поля и некоторые редакторы с Raw Input могут не принимать синтетический ввод.
* Максимальная длина отслеживаемого слова — 50 символов. При превышении лимита буфер инвалидируется; исходный текст не удаляется.
* Автоматическое выделение слова двойным кликом мыши удалено: оно меняло позицию курсора и конфликтовало с программами захвата экрана.
* LayoutSwitcher не изменяет системные настройки Sticky Keys. Если в Windows включён вызов Sticky Keys пятикратным Shift, его можно отключить в параметрах специальных возможностей.
